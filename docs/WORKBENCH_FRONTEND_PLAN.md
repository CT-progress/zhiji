## 阶段 A · 框架迁移（已完成）

目标（已完成）：把迁移前的单流 vanilla 应用换成 Vue 多工作台外壳，① 视频解析工作区在新框架里跑通。此阶段不碰视觉设计，先用朴素可用 UI 验证骨架。

### A1 脚手架与联调通路
- 在仓库根新建 `frontend/`，初始化 Vite + Vue 3 + Pinia。
- 配置 Vite dev server：`/api` 反代到本地 FastAPI（`:8000`），开发时前端跑 Vite、后端跑 uvicorn。
- 生产构建：`vite build` 产物落 `frontend/dist/`；FastAPI 当前已优先托管 `dist/`（`/` 返回 `dist/index.html`，`/assets` 挂载静态）。旧 `/static` 与 `config.html` 仅作未构建产物的兼容回退。
- 跑通最简「Vite 首页 → 调 `/api/health`」确认通路。

### A2 工作台外壳
- 先实现左侧竖排导航栏：五个工作区图标 + 短标签（① 视频解析 ② 笔记与待办 ③ 知识库 ④ 文档助手 ⑤ 媒体工坊），顶部全局区（用户名 / 设置 / 凭据）；B 阶段方向一已将其替换为 Bento 首页 + Dot Dock。
- Pinia store：`auth`（登录态）、`ui`（当前工作区）、`core`（models / settings / 平台凭据，复用现有 `/api/models` `/api/settings`）。
- 外壳只负责切工作区、把主区让给对应组件渲染；每个工作区是一个 Vue 组件。
- 鉴权沿用现有 cookie，Vite 反代后 cookie 同源，无需改后端。

### A3 迁移工作区①（视频解析）
- 把现有 `app.js` 的视频解析 + 会话 + 流式笔记生成逻辑迁入 `frontend/src/workspaces/VideoWorkspace.vue`，通用请求与 SSE 逻辑放在 `frontend/src/lib/`。
- 业务逻辑（`api()`、`streamSSE()`、提交任务、查状态、读流式 delta）照搬，不重写。
- 会话列表降级为 ① 工作区内部子侧栏，不再是全局主结构。
- SSE 流式用 `fetch` + `ReadableStream` 读，Vue 组件用 `ref` 持有增量。
- 此阶段只迁 ①，②③④⑤ 在外壳里先放占位页（"建设中"），阶段 C 再实现。

### A4 验证与旧代码清理
- 跑通：注册 / 登录 → 选平台 → 提交链接 → 解析 → 生成笔记 → 对话 → 设置模型 / 凭据。
- 确认无回归后，把 FastAPI 入口切到 Vue 产物；旧 `web/static/app.js` / `app.css` / `config.html` 保留为兼容回退，不删，便于回滚对照。
- 提交。

## 阶段 B · UI 重设计（已完成 · 方向一）

目标：定下工作台视觉语言并应用到外壳 + ① 工作区，给后续工作区立模板。

### B0 先读 skill
- 开工前先读 `oil-ui`（设计判断，中文场景契合）与 `design-taste-frontend`（反模板化、审计优先）两份 skill，按其方法做。
- 调性锚点：SaaS / 运营工具型，安静、密集、可反复操作；不要营销页、不要大 hero、不要装饰性卡片堆叠。
- 复用现有设计 token（`--bg` `--surface` `--accent #10a37f` 暗色工作调），不另起炉灶。

### B1 设计语言定稿
- 定：色板（暗色基底 + 一个强调色，避免单色族垄断）、字号阶梯（紧凑工作面，不用 hero 级）、间距栅格、卡片圆角 ≤8px、图标用 lucide-vue-next。
- 产出一份 `frontend/DESIGN.md`（token + 组件清单：侧栏项、工作区容器、列表行、表单、状态徽章、流式消息块）。

### B2 应用到外壳 + ①
- 重做外壳与 ① 工作区视觉，对齐 DESIGN.md。
- 用 Playwright 截图桌面 1440×900 / 1280×800 两个视口验收：无重叠、文字不溢出、流式消息不跳布局。手机端不属于 v0.1.0 验收范围。
- 提交。此阶段结束才动 ②。

## 阶段 C · 后续工作区（MVP 已交付，增强项待补）

顺序与理由（依赖从少到多、能最快看到界面成型优先）：

1. **② 笔记与待办**：notes / todos 已交付 MVP；reminders / 日程 / 习惯打卡仍待实现。
2. **③ 知识库**：资料库 / 文本导入 / 阅读 / 混合检索 / 引用 / 资料问答已交付 MVP；PDF / Office 解析待补。
3. **④ 文档助手**：MVP 已完成。单文档 CRUD、自动保存、笔记 / 知识库取材、总结 / 问答 / 续写 / 润色与 Markdown / 纯文本导出已可用；批处理、复杂格式转换和 `doc_jobs` 异步任务仍待实现。
4. **⑤ 媒体工坊**：MVP 已完成。桌面三栏提供媒体库、预览工作台、处理与产物轨道；上传使用 raw body 与真实进度，处理动作接 `tasks` 队列，可选 Whisper 生成 SRT。转码与裁剪使用 PyAV，不依赖系统 FFmpeg。

新工作区继续按「表 + 仓储 + Vue 组件」分层；耗时解析与导出再接入 worker handler。每个工作区独立提交，互不阻塞。

### C⑤ 媒体工坊落地要点

- 页面结构固定为「媒体库索引 / 预览工作台 / 处理与产物轨道」，优先桌面工作流；窄屏样式仅做兜底，不属于本阶段验收重点。
- 多文件按顺序通过 XHR 上传，显示真实字节进度；上传完成后刷新素材列表并选中最新素材。
- 素材支持图片、音频、视频内联预览，SRT 以文本预览；视频支持提取音轨、MP4 转码、按秒裁剪，音频支持抽音轨与裁剪。
- 处理任务轮询进度并保留历史，可取消；产物支持预览、下载与两段式删除。
- `/` 聚焦媒体搜索；操作按钮按素材能力置灰并给出原因。

## 不做清单（防越界）

- ❌ 不引 React / Svelte，定了 Vue 就不摇摆。
- ❌ 不引重型 UI 库（Element Plus / Ant Design）除非 B 阶段证明必要；先用原生 + token。
- ❌ 不在 A 阶段动视觉（A 是骨架验证，B 才是视觉）。
- ❌ 不在 B 阶段加新工作区（B 只立模板，C 才加工作区）。
- ❌ 不一次重写全部五个工作区；逐个迁、逐个提交。
- ❌ 不动后端业务逻辑（平台适配器 / 转写 / LLM / worker / 加解密），前端改造只动表示层与前端状态。
