# 知记工作台 · 产品定位

> 版本：v0.3（2026-10-27） · 形态：本地智能工作台第一版 · 后续：第二版可向 SaaS 演进

## 一句话定位

知记从「单平台视频转笔记工具」升级为**面向个人使用的本地智能工作台**——一个本机运行的统一界面，把碎片化的内容加工（视频解析、笔记、待办、知识库、文档处理、媒体处理）收拢到一处，所有数据留在本地，不依赖云托管。

## 给谁用

- **独立创作者 / 自学者 / 知识工作者**：日常有大量视频、文档需要整理成可检索、可复用的笔记与知识库。
- **单人或小范围自托管用户**：在一台机器上自己用，不对外开放注册。
- **后续演进**：第二版按需开放多租户、走向 SaaS，但第一版不为此做架构妥协。

## 解决什么

- 内容散落各处：视频在平台、笔记在 Obsidian、待办在另一个 App、文件在网盘，互相找不回来。
- 加工链条断裂：抓取、转写、成稿、入库分属不同工具，每次都要手动搬运。
- 资料无法问答：本地文件只能按文件名找，不能语义检索、不能基于资料问答。
- 媒体处理零散：字幕提取、音频转码、片段裁剪要开几个工具来回切。

知记把这些动作收拢到**一个本机界面**，共享同一套任务编排、同一套知识库、同一套凭据管理。

## MVP 包含哪几个工作区

| 工作区 | 能力（MVP 范围） |
| --- | --- |
| **① 视频解析** | 已有的多平台视频解析成笔记链路（抖音 / B 站 / 知乎 / 小红书），保留不动 |
| **② 笔记与待办** | 笔记 CRUD、任务 / 提醒 / 日程、习惯打卡；笔记可一键来自视频解析产物 |
| **③ 知识库** | 项目资料库、本地文件上传、文档解析、全文检索、向量检索、基于资料的问答；自动导入知记生成的笔记 |
| **④ 文档助手** | 单文档写作、总结 / 问答 / 续写 / 润色、笔记与知识库取材、Markdown / 纯文本导出；批处理与复杂格式转换后续补 |
| **⑤ 媒体工坊** | 图片 / 音视频上传预览、搜索重命名、提取音轨、MP4 转码、片段裁剪、可选 Whisper 字幕；处理由 PyAV 在本机完成，产物可下载 |

五个工作区共享同一后台进程、同一数据库、同一任务队列、同一份用户隔离与凭据加密。

### v0.1.0 发布验收（2026-10-27）

本版按**桌面浏览器工作台 + 自托管单机**口径完成发布候选验收：

- 质量门禁：Ruff、mypy（63 个源文件）与 pytest（429 passed / 1 skipped）通过。
- 稳定性：双账号隔离 47/47、重启持久化 26/26、备份恢复 26/26、迁移幂等与全新安装闭环通过。
- 体验：API 冒烟 13/13；桌面 UI 在 1440×900、1280×800 下 65/65，覆盖空状态、长列表、超长标题、横向溢出、遮挡、错误 Toast 与控制台异常。
- 交付工程：前端生产构建通过，Dockerfile 已接入 Node 20 多阶段构建，quickstart 与 CI 已补齐前端构建。
- 收口边界：本机没有 Docker CLI，真实 build / start / health 由 CI 的 Docker job 验证；通过后再创建 v0.1.0 标签。

详细证据与复跑命令见 `docs/RELEASE_ACCEPTANCE.md`。

当前边界：

- ② 尚未从视频解析结果自动生成笔记，也尚未提供提醒、日程和习惯打卡。
- ③ 尚未支持 PDF / Office 解析，也尚未自动导入知记生成的笔记；检索使用中文 n-gram + 本地哈希向量，不依赖外部向量服务。
- ④ 当前完成单文档闭环，AI 结果默认停在协作操作台，由用户决定插入、替换选区、替换全文或复制；批处理、复杂格式转换和基于 `doc_jobs` 的异步任务尚未实现。
- ⑤ 当前完成单文件媒体闭环，单文件默认上限 512 MiB；视频处理使用本机内置 PyAV，不调用系统 FFmpeg，字幕能力需要安装可选 `asr` 依赖。批量转码、复杂滤镜和云端导出尚未实现。
- Docker 镜像已包含 Vue 构建产物与健康检查契约；本机只完成静态验收，真实镜像构建与启动由 CI 收口。
- 「已实现 / MVP 已实现」表示主链路可用，不表示上表中的 MVP 范围已全部交付。

## 明确不做什么（防越界，硬约束）

以下在第一版**坚决不做**，写下来防后期范围漂移：

- ❌ **不做对外开放注册的 SaaS**。第一版只服务本机一个或几个账号；多租户、计费、备案、公网 TLS 留到第二版。
- ❌ **不做移动端原生 App，也不把移动端适配作为阶段 C 的交付项**。当前目标是桌面浏览器工作台。
- ❌ **不做桌面端打包（Electron / Tauri）**。当前形态是「本地前后端一体起」，桌面化是后一步。
- ❌ **不做分布式 / 集群 / 多机房**。单机进程 + 本地数据库 + 本地文件卷就够。
- ❌ **不做微服务拆分**。单体模块化没做透之前不拆服务。
- ❌ **不继续扩张抓取平台**。4 个平台已证明适配器可扩展，第 5 个只增维护成本。
- ❌ **不做对象存储服务（MinIO / S3）**。本机用具名文件卷即可。
- ❌ **不做团队协作 / 共享 / 权限树**。单人 / 自托管场景不需要。
- ❌ **不做内置大模型推理**。LLM 一律走外部 API（已配的兼容 OpenAI 协议的端点），不在本地跑模型权重。
- ❌ **不做学术站全文批量抓取**。合规红线。

第二版要演进 SaaS 时，哪些约束放开、按什么顺序放开，单列在演进路线文档里，本文件不展开。
