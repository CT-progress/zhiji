# D8: 产品形态：自托管优先，不做 SaaS

- **状态**: 已采纳
- **日期**: 2026-10

## 背景

公网开放把项目性质从「工程质量」变成「运维与合规责任」：需要备案、防滥用、数据安全合规、成本控制。对本项目的两个目标（工程质量展示 + 自托管闭环）都几乎无增益，反而分散精力。

## 决策

产品定位为自托管知识加工服务，不提供对外开放注册的 SaaS 形态。

## 备选方案

1. SaaS 模式——可以触达更多用户，但运维/合规/成本负担重。2. 混合模式（自托管 + 可选 SaaS）——复杂度最高，需要同时维护两条路径。3. 开源 + 自托管——已采纳。

## 推翻条件

明确要做开放注册的产品，且愿意承担备案 / 滥用 / 成本时。
