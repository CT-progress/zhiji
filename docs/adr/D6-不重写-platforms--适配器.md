# D6: 不重写 platforms/ 适配器

- **状态**: 已采纳
- **日期**: 2026-10

## 背景

四个平台的适配器经过阶段 0-4 的迭代，已有真实 Cookie 签名、字幕优先、API 签名等成熟实现。用 Java 重写这些适配器是负信号：重写同类代码不产生新价值，反而引入新 bug。

## 决策

平台适配器（抖音 / B 站 / 知乎 / 小红书）是核心资产，阶段 6 Java 控制面不重写适配器，通过 HTTP 调用 Python worker。

## 备选方案

1. 用 Java 重写所有适配器——工作量巨大，且 Playwright / faster-whisper 在 Java 侧不成熟。2. 用第三方抓取 SDK——多数平台无官方 SDK，第三方库维护性不可控。

## 推翻条件

不推翻。适配器是核心资产，长期保持 Python 实现。
