# D4: 语言策略：先 Python，后 Java 控制面

- **状态**: 已采纳
- **日期**: 2026-10

## 背景

同时学一门新语言和做业务是双重风险：语言不熟会写出隐藏 bug，业务不熟会做错方向。Python 是作者最熟悉的语言，FastAPI + SQLAlchemy + Playwright 能在阶段 1-5 跑通完整闭环。Java 的价值在鉴权协议、分布式限流、编排补偿、可观测——这些是阶段 6 的责任。

## 决策

先用 Python 完成数据面和全功能闭环，阶段 6 再以 Java Spring Boot 构建控制面。

## 备选方案

1. 全 Python——简单，但 Spring Security / Resilience4j / Micrometer 等生态在 Python 侧没有对等替代，且 Java 控制面是作品集的差异化展示。2. 全 Java——能展示 Java 能力，但 Playwright / faster-whisper 在 Java 生态不成熟，迭代速度慢。

## 推翻条件

阶段 6 已执行此策略，控制面用 Java、数据面保持 Python。
