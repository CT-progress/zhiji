# D9: 阶段 6 按责任切分，不按接口重写

- **状态**: 已采纳
- **日期**: 2026-10

## 背景

重写同类 CRUD 是负信号：不产生新价值，反而引入新 bug。Java 的价值在于 Spring Security JWT 资源服务器、Redis 令牌桶限流、Resilience4j 熔断、RabbitMQ 编排补偿、Micrometer 可观测——这些是 Python 侧没有对等替代的能力。

## 决策

Java 控制面按职责（鉴权、限流、编排、审计）切分模块，不按 Python API 接口逐一重写。

## 备选方案

1. 按 Python API 接口逐个重写——CRUD 重写是负信号，且 Java 控制面与 Python 数据面的接口一一对应毫无增量。2. 只做只读聚合薄层——太薄，无法展示 Java 生态价值。3. 按责任切分——已采纳，每个模块解决一个明确问题。

## 推翻条件

若 Java 侧只做只读聚合之类的薄层，说明切分过度，应收敛为单一服务。
