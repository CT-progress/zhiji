# D7: 会话默认入库，保留 JSON 回退

- **状态**: 已采纳
- **日期**: 2026-10

## 背景

会话数据天然是追加写入，SQLAlchemy 的 messages 表支持并发追加且可查询。但早期版本用 JSON 文件存储，已有用户数据需要平滑迁移。回退开关让迁移可逆：如果数据库方案有问题，改一个环境变量就能回到 JSON。

## 决策

聊天会话默认存入数据库 messages 表，保留 `ZHIJI_CHAT_BACKEND=json` 环境变量可回退到 JSON 文件。

## 备选方案

1. 只用 JSON 文件——不支持并发追加，无法查询历史。2. 只用数据库——迁移不可逆，早期用户数据丢失风险高。3. 用 SQLite WAL 模式——已采纳，WAL 支持并发读 + 单写。

## 推翻条件

并发写入成为瓶颈时切 PostgreSQL；回退开关在数据库方案稳定后可移除。
