# D2: 异步先用任务表 + 进程内 worker

- **状态**: 已采纳
- **日期**: 2026-10

## 背景

抓取、转写、LLM 加工都是长任务，必须异步化。但单机自托管场景下引入 RabbitMQ / Redis 等中间件会显著增加部署复杂度和运维负担。阶段 1-5 的目标是验证产品逻辑，不是搭建分布式基础设施。

## 决策

异步任务处理先用数据库任务表 + 进程内后台 worker 实现，不过早引入 MQ。

## 备选方案

1. Celery + Redis/RabbitMQ——功能完备，但单机部署多了一个 broker 进程和结果后端，且 Celery 的配置复杂度对早期迭代是负担。2. RQ (Redis Queue)——更轻量，但仍需 Redis。3. asyncio 后台协程——不需额外组件，但不支持多进程 worker、无重试/DLQ 机制。

## 推翻条件

需要多机部署时换 Celery/RQ；阶段 6 Java 控制面已引入 RabbitMQ 作为正式 MQ。
